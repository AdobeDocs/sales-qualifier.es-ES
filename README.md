# Contribución a la documentación de

Agradecemos las contribuciones de los miembros de la comunidad y los empleados de Adobe.

## Código de conducta de código abierto de Adobe

Este proyecto sigue el [Código de conducta de Adobe Open Source](code-of-conduct.md) o
el código de conducta de [.NET Foundation](https://dotnetfoundation.org/code-of-conduct).
Para obtener más información, consulte [Contribución](contributing.md).

## Contribuciones al contenido de Adobe

Si no es empleado de Adobe, puede enviar una contribución de la comunidad. El equipo de documentación revisa las contribuciones en el repositorio público y sincroniza los cambios aprobados con los sistemas internos de Adobe.

Si es empleado de Adobe, contribuya directamente al [repositorio privado de GitHub](https://git.corp.adobe.com/AdobeDocs/) de Adobe. Para obtener más información, consulte la Guía de creación de Adobe Experience League para empleados de Adobe.

## Colaboradores externos

### Cambios menores

Si su contribución es una actualización menor:

1. Vaya al tema que desee editar.
1. En el **¿Fue útil este contenido?** titular en la parte inferior de la página, seleccione **Opciones de comentarios detalladas**.
1. Seleccione **Sugerir una edición** y envíe una solicitud de extracción (PR) con sus cambios.

   Para obtener más información, consulte la [guía para colaboradores de Adobe Docs](https://experienceleague.adobe.com/es/docs/contributor/contributor-guide/introduction).

Las correcciones o aclaraciones menores que envía para la documentación y los ejemplos de código de este repositorio están incluidos en las condiciones de uso de Adobe.

### Principales cambios y nuevos temas

Para crear un tema o proponer un cambio importante, envíe un problema desde la pestaña **Problemas** en el repositorio Git correspondiente. Un miembro del equipo de documentación de trabaja con usted para acordar un plan y publicar la revisión.

>[!NOTE]
>
>Si envía cambios importantes en el código o la documentación, la solicitud de extracción le pedirá que complete un contrato de licencia de colaborador en línea (CLA). Complete el CLA antes de que el equipo de documentación revise la solicitud de extracción.

### Herramientas

Utilice la interfaz de GitHub para realizar ediciones básicas. Para contribuciones importantes, ramifique el repositorio.

Consulte la [guía para colaboradores de Adobe Docs](https://experienceleague.adobe.com/es/docs/contributor/contributor-guide/introduction) para obtener más información.

## Colaboradores internos

Si es redactor técnico de Adobe, administrador de programa o desarrollador de producto que crea artículos técnicos, use el [repositorio privado](https://git.corp.adobe.com/AdobeDocs).

## Dar formato al tema

Los artículos de este repositorio utilizan GitHub Flavored Markdown. Para obtener ayuda, consulte lo siguiente:

* [Conceptos básicos de Markdown](https://help.github.com/articles/getting-started-with-writing-and-formatting-on-github/)
* [Hoja de trucos de Markdown imprimible](https://guides.github.com/pdfs/markdown-cheatsheet-online.pdf)

## Etiquetas

El repositorio público asigna automáticamente etiquetas a las solicitudes de extracción:

* **Cambio enviado al autor**: se notificó al autor de la solicitud de extracción pendiente.
* **lista para combinar**: la solicitud de extracción está lista para su revisión.
